# 技术教程 PPT 制作

> **语言 / Language** · **简体中文（当前）** · [English →](SKILL_en.md)

For English-language tasks, follow [the English instructions](SKILL_en.md) and their English references. Respond in the language requested by the user.

让读者通过 PPT 理解关系、跟随演示并复习，通过配套 Markdown 独立完成实验。读者有编程基础，也可能初次接触当前专题。不能用变量表、命令堆积、术语清单或官方链接代替讲解。

本技能归纳用户在 Zephyr 教程中反复确认的制作要求。以用户当前指令和最新保存的文稿为准；项目专用事实不推广为所有项目的规定。不把技能变成额外审批环节，也不因规则很多而只交付规范、样章或检查报告。

## 选择当前工作方式

- **仅排版或配色：** 保留技术内容、代码、截图、备注和图表含义，修复布局与视觉分类。不要顺手重写教材。
- **结构整理或拆分：** 盘点现有信息单元，按完整主题移动，保留前提、分支和实验，同步编号与所有引用。
- **补充或重写：** 用户说“看不懂”“没有讲清楚为什么”时，修复实际讲解链与示例。只加图例、来源或备注不算解决。

先核对目标绝对路径与所属 Git 根目录。用户指定路径优先于应用保存的旧副本；出现冲突先说明，不能在同名旧目录继续。读取适用的 AGENTS.md、当前目录说明、配套 MD、PPT 及生成/重建入口，检查已有未提交修改。

实际制作 PPT 时，若当前环境提供 `presentations:Presentations` 技能，同时读取它负责原生文件操作、工具选择与验证；本技能负责教学质量和用户风格。只总结规则时不要求启动 PPT 作者工具。依赖路径从当前技能目录和运行环境发现，不能照搬某次缓存版本路径。

## 编排与讲解的基本契约

1. 从真实应用或读者眼前的问题开始，先建立对象和职责，再讲输入、机制、动作与观察结果。
   正文须让读者不打开引用也能理解并操作；源码由作者查证、提炼规则，再在正文讲透。链接、文件名和“自行阅读源码”不能代替解释。整改时同时检查既有正文与 PPT 的错误关系，不能只追加一页正确结论。
2. 每个核心主题独立成模块，交代前置输入、当前任务、完成产物及后续入口。通用架构单独解释，具体模块回顾相关接口后讲自己的模型。内容多时合理拆分，不以缩小字体、省略前提或压缩成提纲收尾。
   用户给定页数上限时，先按核心问题分配页数（含封面），合并重复概念，详细排错和进阶分支留在 MD；不能把上限当成必须填满的目标。融合另一份 PPT 时先提取它补足的关系、例子与依据，不把两份内容顺次拼接。
3. Markdown 写完整解释、分支、操作、输出判断和恢复；PPT 按相同顺序精讲关系和关键动作。不能把 MD 整页贴进 PPT，也不能把执行前提藏在备注中。用户没要求或项目没有配套 MD 时，不凭空扩大为整套书籍。
4. 每个操作说明系统、终端、工作目录、前提、完整动作、可观察结果及失败后的返回点。每个文件首次使用说明它的来源、何时应存在、由谁产生。
5. 工程接入先从使用方解释：输入交给谁、谁读取、如何发现、生成什么、怎样参加构建。不能从“文件存在”跳到“工程自动识别”，也不能只描述包内部结构而不解释外部调用入口。架构讲解须区分接口职责、实现复用范围、实例配置和源码维护边界；目录位置本身不能证明分层或通用性。先说明选用组件的理由及替代路线的责任，再要求下载。
6. 关键结论给出紧邻的官方说明入口、仓库文档路径和实现定位。解释网页的具体站点与入口，不能只写“搜索 Repositories”。依据要可查，理解不能依赖读者先全仓搜索。

## 视觉与编辑的基本契约

- 保留当前封面、主讲人、截图、批注、手工配色和布局调整。修改前备份最新保存稿；旧生成器不能覆盖新内容。
- 变量/参数、文件/路径、接口函数、终端命令分别标色。同类对象在正文、代码和图中一致，图例与文字共同解释类别；具体颜色见视觉参考。
- 代码使用连续、可编辑的原生文本区，通过富文本上色，不能拆成词语文本框、图片或不可执行的省略片段。长操作保留完整可打开复制的文本材料。
- 正文、代码、表格与图内多行文字默认采用 1.2 倍行距，使用真实段落行距属性，不用固定磅值或插空行模拟。段间留白单独控制，调整后复查溢出与相邻对象；不能为塞下内容缩小字号或压回单倍。标题、封面和单行页脚保留系列版式，具体执行见视觉参考。
- 按关系使用思维导图、流程图、时序图；阶段图保持编号和当前位置一致。配套 MD 保留 Mermaid 源，PPT 保留可维护图示。图应回答具体问题，不能替代因果说明。
- 正文颜色与背景成对考虑，检查浅色、暗色阅读；固定浅底却让文字跟随暗主题是已知失败模式。MD 不硬编码 PPT 的文字色。
- 个人系列采用母版非正文页脚署名，正文自动页码统一右下角，封面保留主讲人且不显示页码。不得回退为覆盖正文的斜向大水印。新品牌、其他作者依其现行模板。

## 完成条件

按 [验收流程](references/revision-and-delivery.md) 分别核对初学者理解、技术依据、命令文本、视觉渲染和文件完整性。至少能回答：读者是否知道做什么、为什么这样做、在哪里做、谁读取输入、成功看哪里，以及怎样安全继续或恢复。

正式文件、配套 MD、备注、导航、命令材料和重建源按本次影响范围同步。导出有效不等于 PowerPoint 无修复提示，渲染成功不等于实验通过，旧构建日志不等于本轮实测。说明真实验证范围，不以自动检查代替逐页阅读。

遇到全局反馈，落实到所有受影响正式材料；不能只修改规则或对话回复。相同问题再次出现时检查本轮执行和验收遗漏，不把既有规则缺乏执行归咎于技能。

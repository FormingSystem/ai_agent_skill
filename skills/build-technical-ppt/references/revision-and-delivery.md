# 保留修改、同步与验收

**简体中文** | [English](revision-and-delivery_en.md)

## 最新保存稿是基线

修改前核对完整路径、Git 根与当前目标文件，记录目标文件摘要和时间，备份最新稿。检查封面、截图、文字颜色、备注、批注、用户调整的空行与图形位置。现有生成器和原生重建源可能落后，不能默认它们是最新内容。

PPT 打开且有未保存编辑时，先通过可用的文档会话读取或采用安全副本；不要强行关闭用户文稿。只有确实无法取得最新内容或写入被占用文件时才说明具体阻碍，已有修改授权不再重复确认。保存正式稿前再次比较起始摘要；若用户期间另存，重新以新稿合并，不能直接覆盖。

仅样式修改以原始结构为基础，保留不相关媒体、关系、备注、母版与图层。直接修改 OOXML 时检查关系目标、ID、内容类型、母版/版式登记和 XML 元素顺序；“ZIP 可以解压”不足以保证 PowerPoint 无修复提示。采用当前可用演示工具的安全作者流程，不把某次临时脚本或工具缓存目录固化为依赖。

## 拆分和同步

独立主题采用连续三位主序号 `P001`、`P002`、`P003`，不使用 `P002_01` 代替新的独立章。平台流程确实不同时用 `_Windows`、`_Linux` 文件后缀，按用户最后约定留在同一专题目录，不再为平台分散入口。

PPT 与配套 MD 同主文件名；正文、幻灯片、备注和配套命令保持相同阶段。MD 放完整解释与分支，PPT 精讲关键关系和动作；有必要的缺图可从 PPT 抽取原图到正文 assets，补观察点及版本/路径说明，截图不能代替命令。

拆分/改名/增删页时同步：

- 正式文件名、封面、章号与小节号。
- 目录、大纲、阅读入口、稳定锚点及页码范围。
- PPT 备注、来源链接、配套命令文件及指向它们的链接。
- 原生重建源、源清单和现有生成入口。

实验目录或构建产物不因章号改变而擅自移动，必要时说明保留的历史标识。只同步本次真正受影响的材料，不借整理扩大到无关代码或全仓风格改造。

## 验收的不同层次

按修改内容选择相应检查，禁止把某一层通过等同于全部通过：

| 层次 | 需要的证据 |
| --- | --- |
| 讲解 | 从初学者起点冷读，前提、对象、因果、动作和结果连续 |
| 来源 | 当前版本的文件、官方说明与实现位置相互对应 |
| 操作文本 | 导出/复制后的命令连续，换行、引号、缩进、续行及注释保留 |
| 图示与版面 | 核对 1.2 倍行距及独立段距，逐页渲染目检，图意、颜色、文字、链接、页脚与页码清楚 |
| 原生文件 | 包关系有效；有 PowerPoint 时正常打开，无修复提示，检查原生渲染 |
| 同步 | 配套 MD/备注/导航有效，当前正式稿与重建稿内容一致 |
| 实验 | 在可执行且已授权的环境验证实际操作；明确平台、版本和未测范围 |

视觉检查不能只看缩略图：查看受影响的完整页面，重点查密集代码、长路径、边界文字、所有母版页脚和明暗主题图。自动边界检查辅助发现溢出，不能代替目检。单纯配色不要求重新烧录或跑无关编译。

原生重建若只是 ZIP 重新打包，比较各部件内容而非整包哈希；ZIP 时间戳和排序会改变整包字节。确认最终交付文件就是验证过的文件，不能验证候选后又另写一个未经检查的正式稿。使用用户指定的格式工具时遵守其交付验证要求。

已有工作区、虚拟环境、工具和构建目录先检查后复用。不得为证明命令正确删除 .west、卸载环境、迁移 Git 历史或重置全局配置；需要这些动作时仍按实际请求和环境约束处理，不由 PPT 编辑授权推导。

## 交付与审阅记录

完成授权范围内的实际文件修改，再简要交付可打开的正式文件。不要把“准备修改”“已经写了规则”称作修改完成。用户要求所有 PPT 时盘点并处理全部受影响文稿，不能只交付示例页。

保存“用户批注、落实位置、验证范围”的维护记录，保留批注来源。只有项目约定要求时更新仓库 AGENTS.md、编写约定和状态文档；不擅自改全局技能、无关配置或长期记忆。技能创建/更新本身按用户明确请求进行。

记录没有运行的平台、无法进行的原生验收与尚未验证的实验，不能以历史成功充当本轮结果。面向读者的 PPT 和备注中不塞作者测试日志或本机维护流程，维护记录留在项目约定位置。

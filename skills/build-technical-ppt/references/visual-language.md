# 图示、配色、封面与页脚

> **语言 / Language** · **简体中文（当前）** · [English →](visual-language_en.md)

## 保留已有设计

先看最新保存的 PPT 及原有手工标色，再制定修改。已经建立的系列封面、截图批注、字号层级和语义颜色是输入约束，不是可随旧生成器重置的装饰。仅调颜色时保留文字、段落、形状几何和备注；需要重排时依据真实溢出和阅读顺序调整。

正文按解释内容选择文字、对照表、代码或图示，不把每页机械排成卡片。命令、接口和关系图保持可编辑。长页先按完整问题拆分，不能靠缩字号挤下所有内容。

## 1.2 倍行距与段间留白

个人技术教程的正文、代码、表格和图内多行文字统一采用 **1.2 倍行距**。在 PowerPoint 中对应“段落 → 行距 → 多倍 → 1.2”，属于段落属性，不是字号乘 1.2 后改成固定磅值。程序处理时确认最终 PPT 保存的确是 120% 行距，例如 DrawingML 的 `a:lnSpc/a:spcPct` 值为 `120000`，并在原生应用中复核。

行距和段前/段后距离分别控制。正文的逻辑段落之间使用段后距，可从 12 pt 起按页面校准；不要依靠空白段落撑版。修复旧稿可把纯排版空段换成段后距，保留非空段落顺序与文字。代码中的空行、缩进、换行有结构意义，完整保留，只改行距。

先保留原字号、文字颜色和对齐，再检查文本框高度、图中节点留白、表格行高及与来源链接/页脚的距离。需要时调整框高和对象间隔，内容仍过多就按完整操作或关系拆页；不压低行距、不缩字号、不删必要讲解来消除溢出。图内居中标签需查看实际文字边界，不能只看形状边界。

封面、标题、单行阶段标签、来源链接、署名与页码沿用现有系列版式；新增多行标题同样优先 1.2 倍并单独检查。Markdown 不具备跨阅读器统一行距设置，不为同步 PPT 而插入 HTML、空行或修改用户全局主题。

## 技术对象的语义配色

以下是用户个人技术教程在浅色画布下已确认的配色；现有材料若有更新的明确设计，先保留并按当前要求处理。

| 对象 | 色值 | 例子 |
| --- | --- | --- |
| 变量、参数、配置字段 | 深橙 `#B84E00` | `BOARD`、`ZEPHYR_SDK_INSTALL_DIR`、`-D`、`cmake-ext` |
| 文件、路径 | 蓝 `#0070C0` | `CMakeLists.txt`、`module.yml`、`samples/hello_world` |
| 接口函数、构建语言命令/宏 | 深绿 `#087B3D` | `find_package`、`target_sources`、`zephyr_get` |
| 终端命令 | 紫 `#A02B93` | `cmake`、`west`、`export` |
| 普通说明 | 深色 `#29263B` | 连贯正文 |
| 辅助标签、页脚 | 灰 `#646173` | 图例引导、署名 |

首次出现时提供小型图例，不要求每页重复。同一对象在正文、代码和图中保持一致，但不是整段涂色；链接保留可识别的下划线样式。颜色是辅助信息，文字仍说明对象类型，灰度阅读不能丢失结论。

按语境判断，不能只做全文正则替换：`cmake` 可以是目录或命令；`Kconfig` 可以是文件或配置系统；`cmake-ext` 是完整字段；`west zephyr-export` 是命令组合；路径中的函数同名片段仍是路径。完整路径整体着色，变量与其值不强行归为同一类。

使用同一文本框内的富文本片段上色，不改变命令和源码的文本内容。对现有文稿调整颜色时，对比导出前后的段落文本，防止拆 run 后丢空格、换行或引号。

## 把抽象关系画清楚

| 要解释的关系 | 适合的图 | 检查重点 |
| --- | --- | --- |
| 系统由哪些部分组成 | 思维导图、层次图 | 分类层级及每部分职责 |
| 一个任务如何完成 | 流程图 | 输入、处理顺序、分支与产物 |
| 谁先调用谁、传什么、返回什么 | 时序图 | 调用方向、阶段与执行边界 |
| 当前在总实验哪一步 | 阶段图 | 同一编号、当前阶段、前后产物 |
| 两种路线有什么差异 | 并列流程或表格 | 相同输入、不同动作、结果与条件 |

图前说明要解答的问题，图后解释关键连接。流程箭头要有真实顺序或依赖含义；时序图区分同进程的脚本调用与独立进程工具，不能把每个文件画成服务。不要为满足“有图”随意堆齐所有图型。

MD 优先保存 Mermaid 源，PPT 同步其图意与阶段。用户要求可编辑图时使用原生可编辑节点和连接；使用渲染图时仍保留源文件，不能宣称图中节点可直接编辑。文字密集的 Mermaid 图按阅读顺序分解，保证最终观看尺寸下可读。

## 明暗主题

Markdown 文字、行内代码和语法高亮默认跟随阅读器主题，不注入固定 HTML 颜色。Mermaid 阶段高亮优先强调边框与线宽，避免只锁浅色填充却保留暗主题浅字。

必须自定义填色时，成对设置前景与背景，复查所有分支、标签和边线。分别渲染浅色、暗色主题，检查所用阅读器的 HTML 标签/SVG 文字差异。PPT 的固定画布单独验色，不直接照搬暗主题截图。对比度测量辅助判断，不能代替最终图像目检。

## 封面、署名和页码

个人系列保留用户选择的背景封面、主讲人 `lizhaojun`。最终约定是每页母版的横向页脚署名，放在非正文区域，取消正文斜向大水印。封面无页码，正文页码统一右下角，显示实际幻灯片序号。

母版位于普通页面内容后方，图片可能遮住它；解决方式是预留页脚区域，要求正文、图片、代码、表格与链接避开，而不是把署名抬到正文顶层。覆盖所有实际使用的母版/版式，新增页自动继承；清理普通页面上的重复署名，检查没有隐藏背景图形。

1280 × 720 个人系列已有尺寸可作为保留参照，换画布按比例核对，不把这些坐标强塞给其他模板：

- 署名框：左 64、上 676、宽 150、高 28；横向左对齐、垂直居中，Microsoft YaHei 13.5 pt，无边框/填充。
- 白底署名 `#646173`，深色封面署名 `#D4CDE8`，文字不透明。
- 页码框：左 1140、上 676、宽 76、高 28，右对齐，与署名同字号。
- 只对署名关闭拼写检查；红色拼写波浪线、形状边线与截图人工标记先区分，不能为了署名关闭全篇校对或误删用户批注。

其他作者、其他品牌和用户明确要求保留的水印按其模板，不自动添加 lizhaojun。

# 维护中英文仓库

> **语言 / Language** · **简体中文（当前）** · [English →](SKILL_en.md)

面向读者完成从首页到正文、参考资料再返回的两条完整阅读路径。英文目录不能替代英文正文，文件存在不能替代可发现的语言切换。For English-language tasks, use [the English instructions](SKILL_en.md).

## 先确定范围与现有约定

- 核对用户指定目录、Git 根、协作规则、当前分支及未提交工作；按已授权范围编辑，不混入其他任务的差量。
- 盘点 README、贡献与治理文档、技能主指令、全部被引用的参考文档和真实阅读入口。用户要求全仓双语时不能自行缩成首页翻译。
- 检查已有语言目录、文件后缀、文档 ID、生成器和阅读器；复用可维护的现有方案。没有约定时，可采用原文件和同目录 `_en.md` 配对，使用相对链接。
- 区分自有可翻译正文、共用代码与配置、原始证据和第三方资料。不要翻译真实路径、接口名、命令参数或凭空生成第三方英文页面。原始许可证与版本证据按其来源保留。

## 翻译完整内容并保留契约

逐段处理范围内的正文、列表、表格、图例和非执行性示意文字；保留前提、例外、正常与失败路径、操作边界及证据层次。长文分批处理可以，但必须保留完整待办并完成全部批次。

- 原样保留代码标识、可执行命令、路径、配置键、数字和单位；可译注释或示意文字与执行语法分开处理。双语阅读不意味着复制两套运行代码。
- 技能只保留一套运行注册；在主入口说明语言选择，将相应语言正文和参考资料一起分发。不猜测运行时支持的 locale 字段，界面配置只使用已确认的字段。
- 翻译服务仅可处理允许向该服务提供的材料；未确认的私人内容不外传。机器译稿需要语义复核，尤其是禁止、例外、取消、回滚及时间先后；`stage`、`commit`、`capability`、`fail closed`、publication/release 和 safety/liveness 等词不能按普通语义生硬直译。
- 检查段落、标题、列表、表格、代码围栏和字面代码，发现差异逐项核对。结构一致、哈希匹配和链接通过都不能证明语义等价；不因检查通过就宣称完成逐段人工审稿。

## 让切换入口真实可见

在每篇配对文档的标题下和正文末尾放置醒目的语言导航，标明当前语言，另一语言链接直达同一篇的对应版本。普通正文提到译文、隐蔽注释或仅首页有入口，都不算逐页语言切换。

使用阅读器能渲染的普通 Markdown 导航。Markdown 文件本身通过链接切换页面，不伪称安装了 GitHub 的全局语言控件或客户端偏好记忆；项目已有站点语言路由时按其真实能力接入。

先验证当前文档到译文、再从译文返回当前文档；避免返回首页、同语言副本或另一个主题。长文页尾入口同样需要核验。用户看不到入口时，检查真实文件、版本、渲染视图和位置，不凭印象反复声称已经存在。

## 保持每种语言的连续跳转

- 中文页默认进入中文正文，英文页默认进入英文正文。显式语言切换是跨语言例外；共用资源和没有译本的外部资料按实际语言标注。
- 解析相对路径与片段再更新链接，避免简单全局替换伤及代码、URL、引用例子或文件身份。
- 按实际渲染规则从译后标题建立锚点映射，处理标题编号、标点、重复标题和显式锚点。目录、自链接、跨文档深链和返回入口都要覆盖。
- 留意翻译在 Markdown 链接方括号与圆括号之间插入空白，使检查器漏掉失效链接；也检查强调、表格列和围栏结构。

## 记录覆盖并防止失同步

用一份配对台账登记源文、译文及维护状态；新页面和删除、改名都必须更新配对。项目使用内容摘要时，只有复核两种语言后才更新摘要，不能自动刷新后宣称译文已同步。

复用或补充仓库检查，至少发现：范围内文件未配对、目标缺失、重复登记、译文版本过期、页首或页尾切换缺失、切换目标错误、语言内导航错误及标题锚点失效。为曾经出现的失败补有意义的回归用例，不用仅匹配生成文案的测试代替行为验证。

## 验证与交付

1. 在真实 Markdown 渲染中核对普通参考页、技能长文和有元数据的治理页，检查页首、页尾以及双向跳转；报告哪些页面实际预览过。
2. 执行结构、链接、语言覆盖、相关测试和暂存差异检查；不要用网络请求成功代替链接目的页与正文语言核验。
3. 技能分发时按仓库已有工具预览差异、同步并再次核对；不覆盖未经核对的镜像独有文件，不反向提升安装副本为权威来源。
4. 用户已授权提交或推送时完成对应动作，核对远端提交与本地一致；保留其他未提交工作。汇报完整范围、真实验证和仍存在的限制，不用“支持双语”掩盖未翻译正文。

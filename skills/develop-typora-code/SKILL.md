# TyporaCode 开发

> **语言 / Language** · **简体中文（当前）** · [English →](SKILL_en.md)

For English-language tasks, follow [the English instructions](SKILL_en.md) and their English references. Respond in the language requested by the user.

以当前用户需求和当前产品边界为准。保留可复用的 Typora 原生能力，补齐被明确要求的功能；对照 VS Code 不等于移植全部工作台。让后续消息补充既有需求，不冲掉尚未解决的问题。

## 找到正确工程与状态

- 先确认实际 TyporaCode 根目录；当前 Windows 发现入口是 `F:/git_storage/typora_code`，使用前核对存在性及 `AGENTS.md` 的工程身份。外层会话目录可能仍是 `linux-note`，不要在那里维护第二份实现。
- 先读项目 `AGENTS.md`、`README.md`、`enhancements/README.md`、`docs/development_handoff.md` 和 `.cache/issue_tracking/requirements.md`，再查看相关差量。
- 台账管理编号、待办和本次证据；`docs/requirements_design.md` 管理设计入口；对应领域文档管理权威设计；`docs/feedback_review.md` 管理交付历史。按这个分工更新，不复制多份完成清单。
- 新需求或复现先登记原意、来源日期、验收和状态，再补正式设计。小修复可更新原小节。设计至少讲清触发、预期、取消/失败、状态所有者、实现取舍和验证边界。
- 开始前核对已有修改、已提交内容、实际安装资产和未完成验收项。这四种状态不能互相替代。当前会话已有的授权和用户纠正持续有效。

## 稳定性维护与技能更新

- 在仓库 `docs/stability_testing.md`、`docs/stability_issues.md` 和测试目录读取当前分类、用例及证据规则；需求和测试定义以版本控制内资料为准，不能仅靠会话记忆或旧通过数量。
- 新反馈先关联稳定需求/问题编号，补充领域设计与实现方案；沿实际命令、状态所有者、平台适配和刷新订阅者分析影响，再实施。发现同类问题扩查真实调用方；根因未证实就明确标为假设。
- 用例分别记录单元/功能/系统层级和实现/压力目的。20、100、1000是按成本选择的实际工作负载，不是全套UI盲目重复次数；记录取消、迟到、并发、清理和关联模块不变量。
- 复用仓库统一测试目录和运行器。运行证据关联需求、设计、实现、用例、版本、环境和资产摘要；未执行、平台不足、失败及替身边界明确保留，复跑不得覆盖失败证据。
- 当前路由是 `enhancements/tests/test_catalog.json`、`npm run test:quality` 与 `docs/stability_testing.md`；原生稳定性用仓库的 `test_stability_native.ps1`，先按文档准备独立副本，不依赖历史缓存脚本。自动运行报告为 incomplete 时逐项解释，不能概括成全通过；候选在测试期间变化需要补验对应最终资产。
- PowerShell构建后显式核对退出码，失败就停止准备与安装；私有宿主受测脚本摘要必须匹配本次候选。运行器完成还须读取功能checks结果，不能用运行器的零退出码代替验收。Windows占用导致的旧dist测试不得作为新源码证据。
- SSH接入按`docs/remote_ssh.md`从主“打开文件夹”进入资源树，验证主文件服务、搜索、Git与终端的同一远端身份；独立SSH读写或旁路源码标签不足以验收本地式远程工作区。原生Markdown须实际编辑渲染、保存后独立SSH回读，并覆盖图片、中文链接、导航、冲突和断线；终端按R070.5与文件连接共享认证协调器，外部正文刷新与会话恢复按实际能力分别报告。多账号验收同时核对主机/用户/端口及配置身份、窗口工作区所有者及拆分/重启；R070.7要求其他SSH或本地终端先切换整个工作区，取消保留原对象，不能在同窗口绕开所有者；密码不可写PTY、命令行、环境或普通配置。系统凭据必须真实往返，测试使用独立命名空间并在完成回执之前清理。R070.6的查看保险箱与自动登录域独立：重置只清查看记录，不能删除或自动回填自动登录密码；补验错误保险密码、跨窗变更、关闭/失焦隐藏及重置后重新配置。
- 问题按领域和根因聚合，重复反馈更新原条目；本地台账记录当前进度，正式问题索引便于跨机器检索，交付历史只记录交付事实和证据入口。
- 当新需求、仓库架构或已验证失败使技能约定过时时，及时更新本技能的对应规则及路由，并验证；不把一次缺陷扩写成无关任务的普遍限制，不继续沿用已被用户替代的约定。

## 对照上游先核对行为

查 `docs/vscode_design_baseline.md` 的固定版本与提交，再针对当前控件读取上游源码、有效配置及官方图标来源。研究结果和短期源码放项目忽略的 `.cache/`，不成为运行依赖。

一次对照要能回答：入口实际调用哪个命令、命令如何确定对象、何时启用、是否需要选择、何时确认、执行后怎样更新。视觉对照再说明采用的尺寸/状态规则及目标控件；区分上游常量与本产品适配值，不凭截图估算“一比一”。

例如本次已核对的 VS Code 1.137.0 Git 来源：

- `extensions/git/package.json`：菜单注册、组序和启用条件。
- `extensions/git/src/commands.ts`、`repository.ts`：快捷动作、目标解析、丢弃分类、回收站和错误边界。
- `extensions/git/src/historyProvider.ts`、`icons.ts`：引用、短提交号、分类及图标语义。
- `src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts`：历史引用多选及接受/取消。
- `src/vs/platform/quickinput/browser/`：QuickPick 布局、选择与键盘规则。

这些是定位入口，不把固定版本永久写成新任务的默认答案；若项目基线变化，重新核对。使用官方 Codicons/Seti 原始资源，维护现有来源清单、Git blob、SHA256 和映射文档，不能自画近似图标或借无关图标替代。

## 按职责组织实现

- UI 拥有呈现、局部选择草稿、布局与交互；控制器/命令服务拥有业务状态、目标解析和串行执行；宿主适配集中调用已查证的原生接口。
- 同一动作的侧栏、底栏、快捷键和更多菜单调用同一业务入口；不要各自拼参数、直接执行命令或维护另一套忙碌状态。
- 复用项目现有按钮、图标、主题交互、焦点/退出栈、浮层定位和静态样式服务。独立视图保留自己的结构；真正共享的契约统一管理，不建无用途的通用框架。
- 新的监听器、异步请求、DOM 和样式登记必须有明确生命周期。关闭、切库、切文档或销毁后，旧引用及迟到结果不能重新显示或执行。
- 提交浮层Markdown和排版先读`docs/workspace_interaction.md`的R053；核对调用方的compact及HTML/Markdown内容类型，不能按截图放大字号或套用另一种hover最大宽度。正文使用共同安全渲染器。Shadow样式通过`_shadow.css`声明独立作用域，同时验证正式构建保留字符串、全局静态CSS排除它；直接CSS字符串夹具通过不能代替生产构建。私有桌面PrintWindow可能保留旧画面，明暗/缩放须记录实际计算值，不把发出主题命令或截图文件名视为状态已切换。
- 原生Markdown代码块高度问题按各CodeMirror实例核对宽度、可见性和换行缓存；不能按行数强设高度或每帧刷新全部块。观察器和帧任务随文档实例清理，区分高度变化与宽度失效；原生夹具先等运行器窗口准备回执、建立延迟实例，再对可见短块做刷新前后对照，避免外部缩放/离屏采样假失败。
- 原生接口先读已抽取的对应版本代码或现有适配，不猜方法名。打开文件/文件夹继续使用宿主系统选择窗口，不能退化成手输路径。
- 切换目录先读项目 `docs/workspace_switch.md`，走共同工作区生命周期，不能只改挂载路径或只刷文件树。核对系统选择、最近目录、宿主原生目录入口与关闭目录；先保护草稿/进行中的写入，再清理旧编辑组、Git控制器、搜索、固定时间线、导航及终端。以临时双仓库验证根目录、可操作文件和Git身份一致，并覆盖取消、保存失败、迟到结果及连续切换；没有热退出备份能力时不能静默丢弃草稿。
- 工作区恢复沿用`docs/workspace_switch.md`的R040.2：先存旧根会话、暂停采样、清理旧状态，再恢复新根自己的文件；空记录不得回退全局最近文件。原生启动偏好从偏好页`setting.getExtraOption`核对，编辑器`setting.loadAll`不含此项。核心`eachLeaves`为逆序且truthy提前终止，收集回调必须显式void，文件顺序按实际标签采集；测试替身不能用forEach掩盖差异。恢复验收包括原始宿主第二进程读取磁盘记录，不拿内存往返替代重开验证。
- 文件快速打开先读 `docs/quick_open.md`：查询准备、评分、排序与高亮共用固定上游算法，不再各写子串匹配。目录词匹配的是文件路径；对照必须固定工作区，不能跨根拼结果。扫描范围与结果显示上限分别验证；增加候选数量时检查可见行绘制、键盘访问列表末尾和事件循环间隔。测试包含长路径、双斜线形式、多词、引号、显式排除路径、迟到查询/切库与原生入口；不要把匹配规则一致称为全部VS Code历史/排除配置已移植。
- 最近文件/目录管理先读`docs/recent_open.md`的R059，主进程宿主历史是唯一持久化所有者；展示不逐项扫描离线磁盘，选择时区分确定缺失和权限/连接故障。菜单、Ctrl+R和原生目录入口走同一校验/切换服务；清空按确认快照移除历史，不动文档、草稿和工作区恢复记录。真实宿主验收要显式设置恢复偏好，替身路径形式和主进程精确移除保持一致。
- 分屏和跨窗拖动先读`docs/drag_and_windows.md`的R005.1/R005.2/R005.3；压力层分别验证真实布局/DOM比例、编辑器及撤销身份、真实频道清理和原生建窗。记录不滚动时的rAF与活动标签重排的open/close次数，不能只量总耗时；分栏删除前取原索引/权重，嵌套替换保留父份额，调整分隔线检查未参与栏。原生建窗合并使用`test_drag_windows_native.ps1`，显式启用恢复上次文件并覆盖源码、已保存/未保存Markdown；启动意图须在安全锚点被清理前捕获，拖放附窗不恢复或覆盖原目录会话。普通启动、主动切目录与移交建窗分别验收；检查附窗恰好包含指定文件，不能仅断言它存在。同路径不能直接判为冲突，应比较实际内存正文及保存格式；相同内容复用目标模型和撤销，差异保留双方，时间线已保存记录不等同完整草稿备份。拖放不加模态确认，失败使用不抢焦点的共享通知，同时排查失败根因；宿主可能不发送unload，附窗退出用专属renderer进程存活检查，不能把没有unload记录直接判为产品未关闭。区分renderer事件和物理OS拖放、同窗撤销保留和跨进程新历史；只声明实际支持的VS Code操作配置。
- 文件生命周期修复先区分`core.empty`布局占位、空路径真实草稿与宿主缓存；不能按New tab文字或空路径隐藏真实文档。读`docs/explorer_history.md`的R052；连续验证最后文件关闭→磁盘变化→重开、回收→打开另一文件，避免监视器延时掩盖旧正文和隐藏dirty缓存。回收成功不等于宿主释放成功；释放前后核对身份/正文，删除期间新输入必须保留，空状态同步Open Editors、未固定时间线和文档状态。
- 不因改外观而移除宿主依赖节点、接管正文事件或重建整个工作台。遵守项目 `snake_case`，文件读写明确 UTF-8。

Git大仓库改动按`docs/stability_testing.md`的R071.2验证传输、状态投影和UI三个边界；必须覆盖超过旧容量的真实Git输出、UTF-8 BOM/NUL跨块保真和选区暂存、Windows批量路径stdin、取消/超时与实际退出码。主线程心跳和总耗时分别记录；不以async或虚拟行存在宣称完整响应性。Git发现区分缺失和无法执行，已有Git不能为测试卸载；系统安装替身与真实安装证据分开。

Git比较新增或切换呈现方式时，对照原视图的完整导航入口：工具栏前后变更、右侧红绿概览、视口拖动、键盘和正文滚动都要在新视图实测。渲染块高度不能直接沿用源码行位置；覆盖缩放、刷新、无差异和退出后的清理，不能只凭着色截图或工具栏跳转通过就判定比较功能完整。R034.2用例在现有Markdown差异功能与原生夹具中维护。

阅读/预览修复先读`docs/navigation_history.md`的视图分类契约及`docs/git_markdown_diff.md`的R034.3。主编辑区的可编辑正文、源码、只读版本和差异比较均登记统一导航端口，携带资源/版本/组身份及由领域持有的恢复快照；独立浮动预览保持自己的浏览历史，功能面板不伪造文件记录。所有Markdown只读呈现共用主题适配与失效通知，禁止每个模块重新提取CSS或固定覆盖标题/表格皮肤。验收串联来源、目标、打开原文件和前后导航，比较原生与Shadow的实际字体、标题及表格属性，覆盖主题切换、关闭重开、取消及销毁。 链接历史回归必须先建立真实正文选区，再执行Ctrl链接、Alt返回和顶栏pointerdown到click；直接调用导航函数或无选区合成click不能覆盖失焦截断分支。外部浏览器返回须区分端口替身与真实进程焦点，恢复焦点只更新同一编辑器检查点，切到其他文件仍应入栈；历史不得因工具栏点击或闲置丢失前进。

R067.6（2026-09-29）：同编辑器焦点通知不等于文档选区事件；纯工具控件操作不得追加/替换文档历史，失焦前可信位置只暂存到实际离开时提交。回归串联后退、真实活动栏/菜单点击、延迟选区、前进及返回来源位置，并检查正文编辑和起点在侧栏的明确定位仍记录；前进/后退沿同一接口，不靠分别屏蔽按钮补救。

Git内容与来源联动按`docs/git_markdown_diff.md`的R034.4和导航来源契约接入：差异持有仓库、两侧版本及新旧路径，列表仅投影活动来源，不能以最后点击行或同名文件替代。定位来源不重开正文；覆盖失焦选中、标签/导航切换、筛选外提交、改名、取消和虚拟列表末项。首次定位先建立可滚动范围，不能只在现有DOM找行；任意基线比较没有对应变更组时不得假选普通暂存/未暂存行。

文本呈现按R034.5/R034.6统一配置与定位：软换行只改变布局，不改变逻辑行号/正文；默认迁移仅触及目标设置，并保留版本契约后的用户值。模式/宽度转换先捕获当前模型或语义内容锚点，布局后恢复；相同布局的导航仍保留精确滚动快照，用户输入取消迟到恢复。Markdown差异细化需同步概览、键盘跳转和源行映射，未改标题不能因尾部空行染色。Git列表的展开、焦点和活动文件来源选择分离，不用aria-expanded绘制第二条选中背景；普通/虚拟树只缩进内容，整行状态背景共享边界，验收计算样式与长短名称/窄宽/明暗。

- 菜单按R065.2统一采用VS Code列对齐，取消R065.1普通项紧凑例外：所有行文字起点一致，状态只改变图标可见性；条目语义仍区分普通/可勾选。菜单层统一测量快捷键列，核对格式等混合菜单、实际行盒/图标/快捷键、各层子菜单和取消选区恢复。

## 区分选择和执行

普通便捷图标应完成其命名的操作。已知目标由服务自动解析；只有当前事实不能唯一确定目标时，才呈现一次必要的选择。

| 情形 | 处理 |
| --- | --- |
| 刷新、获取等已确定目标的普通动作 | 调用统一命令，反馈忙碌、结果及失败；不加通用“预览/执行”层 |
| 普通拉取/推送 | 读取实际 remote/upstream/分支及有效配置；唯一目标直接执行，多候选才选择 |
| 历史引用多选 | 勾选属于草稿，接受后一次应用过滤范围；取消保持原范围，不检出分支 |
| 放弃更改、删除、强制写入等 | 按本需求和对应上游语义独立确认准确对象及后果，不让这类确认污染普通快捷入口 |

- 分支检出按 `docs/git_branch_checkout.md` 走共享单选入口；历史引用筛选仍是可取消的多选草稿。核对标签剥离、已有跟踪分支、同名标签/分支及完整refs；Git的`--short`可能为消歧保留heads前缀，验收身份用完整ref。原生主题中核对详情行与名称的真实文字起点，避免仅测外框。
- 分支、远端和路径是完整身份，不能按第一个 `/` 简单切割；名称含 `/`、上下游异名、分离 HEAD、空仓和无上游应有明确行为。
- UI 参数不能取代服务校验。异步准备期间捕获仓库/控制器身份；接受前与执行前检查仍有效，避免旧弹层把动作应用到新仓库。
- 本轮丢弃确认的分类是已跟踪恢复与未跟踪回收。恢复以 index 为准，保留暂存内容；未跟踪使用原生回收站。取消零写入，读取迟到不抢默认焦点，确认关闭后只执行一次；部分失败说明已完成部分。
- 产品用户点击按钮是产品运行时授权，不表示 AI 可在开发验收中推送、拉取、丢弃或恢复用户真实仓库。实际 Git 验收用专属临时仓库与本地 bare 远端，必要的真实环境操作依当前会话明确授权范围执行。

## 验证与安全候选

滚动条基础绘制统一走项目 `workspace_scrollbars.css` 与 `docs/workspace_interaction.md` 的 R049 契约，不在面板复制宽度、圆角或三态颜色。先辨认原生伪元素、Monaco/xterm DOM滑块和真正任务进度；保留各自滚动/主题所有者与隐藏契约。Chromium的`scrollbar-width:thin`或非auto颜色可能绕过WebKit圆角，计算值须结合实际截图验证；缩放下真实指针坐标按当前zoom换算，不能把命中偏差误判为产品失效。

滚动条空闲显隐按`docs/workspace_interaction.md`的R049.1处理为全局行为，不能只修截图中的列表。原生overflow区域共用活动状态和绘制属性，Monaco/xterm保留自有显隐；保持布局占位和原生拖动。伪元素transition不能只看CSS声明，验证实际中间透明度和像素。2026-09-20用户明确要求必须渐隐，滚动条单独采用reduceMotion=off有效语义，不能由系统减少动画使800ms归零；测试必须记录实际媒体条件并检查原生中间帧；验证动态/嵌套区域、鼠标与键盘、迟到动画、销毁及第三方边界。

先跑能发现本次失败的目标测试，再按影响执行项目 build/check/UI。同一共享 bundle 的构建串行进行；并行协作者明确文件所有权与接线责任。

- 验证所有真实调用方，不只测新函数。覆盖默认、选中、悬停、键盘、禁用、长名称、窄窗口、明暗与缩放；实际命中和文字行盒也要检查，不能只看外框可见。
- 列宽/分隔条验证实际边界位移与指针方向、相邻区域和及内容对齐，不能只断言CSS变量变了。先辨认弹性轨道与固定轨道，检查最后一列从哪条边界调整；隐藏列、取消/失去捕获、重绘/切库与保存失败需走同一事务。初始几何及无障碍值在节点入布局后采样，Electron真实键码与DOM事件键名分开处理。
- Git 测试核对 HEAD、路径/模式/OID、`ls-files --stage -z`、暂存 diff 以及工作文件字节。Git 正常读取可能更新 index 的 stat 缓存，不能把原始 index 文件字节变化误报为暂存内容变更。
- 临时回收测试必须限制到本轮新建文件。能够读取回收内容时核对原字节；权限不足就如实记录边界，不以永久删除代替回收，也不吞掉真实内容不一致。
- Chromium 真实输入、renderer 合成事件、宿主 API 调用和人工验证分别标明。用例通过数量仅对应实际执行的这一版本；旧截图或旧通过记录不能替代新验收。
- 原生 Typora 验收复用项目私有桌面/独立用户目录夹具和已核对的原始安装资源。不得切换用户桌面、关闭用户进程、改真实偏好或草稿；不要为取图绕过生产调试保护、加 debug 参数或改 ASAR。
- 构建候选先核对安全安装基线与本轮差量。HEAD 含尚未原生验收的其他功能时，不能盲目把整个当前 bundle 安装给用户；用明确的候选资产清单、摘要和已验证依赖构造可审查包。
- 候选原生验收要保存所测脚本/CSS摘要、版本、视口、主题、输入方式、截图、结果与限制，并确认原始正文、dirty 状态及不相关资产保持。
- 菜单验收同时核对实际所有者状态、勾选／未勾选、父级列表字号、宿主伪元素和文字起点；只量SVG大小不能证明勾选或整行留白正确。切换后重开并核对持久化，保留原生主题验证。 菜单工厂的可选快捷键不能随class改变列数；同一菜单共用名称/快捷键列宽，检查实际三项设置菜单的每个文字行盒。不要插入额外长名称撑大菜单后便声称普通菜单完整；极窄窗口按当前设计换行，不以ellipsis掩盖功能名。重复侧栏留白先量活动栏到面板/树根的完整边界并覆盖用户正文主题，区分已安装资产与运行窗口实际加载，不能用组件内部相对值证明外层没有留白。
- 分区／图标层级验收应包含整行外留白、默认/悬停底色、工具区域、正文主题字体隔离与实际SVG尺寸；共用分区角色而不是仅共享箭头坐标。切换面板会卸载其DOM时，应在各面板连接期间分别采集计算样式，不能在离线节点上比较空值。原生截图先确认面板可见命中并完成绘制；调整宽度走真实分隔条入口，同时检查相邻编辑区，不能用测试CSS强制尺寸后只量目标外框。

- 正文是给读者看的修改总结，交代具体问题、触发场景和修改后的行为。不要拿文件清单、模块名或“同步文档/新增测试/构建安装”填充明细；文档、测试、规则本身是目的时，说明指引、覆盖或约束具体如何改变。语法检查不能代替逐条内容审阅，简单结果一条说清即可，不为凑条数重复标题或流程。
- 安装、提交和远端推送遵守当前会话已经确定的范围。只交付本轮已核对文件，不夹带用户无关改动。提交不等于需求完成或安装验收通过；收尾更新台账、设计/交付记录和未决项。

本技能提供决策与项目路由；具体安装路径、候选提交和测试命令从当前项目文档、清单及既有夹具获取，不沿用过期会话值。

底栏回归须覆盖宿主 footer-btn 的隐藏与内边距、not-empty-menu-group、show 强制 block、hide 业务状态以及内层 ty-add 内联 top。适配共享图标内容盒而非每个按钮偏移；切换列表/树后重新检查字形中心，不能只验首次外框。
